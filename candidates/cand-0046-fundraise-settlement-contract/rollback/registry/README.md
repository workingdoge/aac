# registry — 4/REG, the root registry (Solidity)

The deployable surface that **consumes** the AAC proofs. 4/REG holds books, not
funds: its state is commitments, its update rule is proof, and **its refusals
are the entire trust model**. This is where the Noir/UltraHonk world meets a
chain. It enshrines two of the three targets (3/PROOF §4): TRANSITION/1 posts
state transitions, NULLIFY/1 guards historical non-replay. EVENT-COMPLETE/1 is
deliberately **not** here — it is an application target and the base registry
**MUST NOT** require it (4/REG §5: the registry verifies *consistency, not
truth*).

- `src/Registry.sol` — the 4/REG contract.
  - `update(namehash, proof, publicInputs)` discharges the **TRANSITION/1**
    verifier (3/PROOF §5): **old-root equality** (the concurrency rule — each row
    is its own sequencer), the **context pin**, and the **proof** itself, then
    atomically advances the roots, chains `fact_fold`, and bumps the nonce.
  - `advanceNullifier(namehash, proof, publicInputs)` discharges the **NULLIFY/1**
    verifier (3/PROOF §4.2): **old-set-root equality**, the single-insertion bound
    (`count == 1`), and the proof, then advances the row's historical
    consumed-nullifier **set** root. This is the historical anti-replay guard —
    proof that a fresh nullifier is a non-member of the spent set, inserted.
    It is distinct from `update`'s batch-local nullifier chain: the set root is a
    strictly-sorted set (`TAG_SET`), the transition chain is an insertion
    accumulator (`TAG_NULLIFIER`) — a different representation, a different job.
  - Anything it cannot verify, it refuses.
- `src/HonkVerifier.sol` / `src/NullifyHonkVerifier.sol` — the two UltraHonk
  verifiers, **generated by `bb`** (`bb write_solidity_verifier -s ultra_honk -k
  vk`) for the TRANSITION/1 and NULLIFY/1 vks. The nullify verifier's public
  `contract` is renamed (`HonkVerifier` → `NullifyHonkVerifier`) so the two
  co-compile; the internal libraries are file-scoped and need no rename.
  Regenerable; do not hand-edit.
- `test/fixtures/{transition,nullify}.{proof,pub}` — **real** proofs (keccak
  oracle, for EVM) + their public inputs (8 for transition, 4 for nullify),
  produced by `bb prove --oracle_hash keccak`.

The pipeline, end to end:

```
circuits/transition (Noir) → bb prove --oracle_hash keccak → HonkVerifier.sol       → Registry.update()
circuits/nullify    (Noir) → bb prove --oracle_hash keccak → NullifyHonkVerifier.sol → Registry.advanceNullifier()
```

## Test

```sh
cd registry
forge test --use "$(command -v solc)"        # forge + solc from nixpkgs
```

`test_ValidProofUpdatesRow` verifies the **real** TRANSITION/1 proof on-chain
(~3.25M gas); `test_NullifyAdvancesSetRoot` verifies the **real** NULLIFY/1 proof
(~3.05M gas) and advances the historical set root. The `*Reverts` tests exercise
the refusals — stale roots, tampered proofs, context/context-set mismatch, and a
claimed multi-insertion — the trust model. 8 tests.

## Regenerate the verifiers + fixtures

```sh
cd circuits && nargo compile && nargo execute -p transition && nargo execute -p nullify
# TRANSITION/1
bb prove -s ultra_honk -b target/transition.json -w target/transition.gz \
   -o /tmp/t --oracle_hash keccak --write_vk
bb write_solidity_verifier -s ultra_honk -k /tmp/t/vk -o ../registry/src/HonkVerifier.sol
cp /tmp/t/proof ../registry/test/fixtures/transition.proof
cp /tmp/t/public_inputs ../registry/test/fixtures/transition.pub
# NULLIFY/1 (rename the public contract so the two verifiers co-compile)
bb prove -s ultra_honk -b target/nullify.json -w target/nullify.gz \
   -o /tmp/n --oracle_hash keccak --write_vk
bb write_solidity_verifier -s ultra_honk -k /tmp/n/vk -o /tmp/n/V.sol
sed 's/^contract HonkVerifier is/contract NullifyHonkVerifier is/' /tmp/n/V.sol \
   > ../registry/src/NullifyHonkVerifier.sol
cp /tmp/n/proof ../registry/test/fixtures/nullify.proof
cp /tmp/n/public_inputs ../registry/test/fixtures/nullify.pub
```

## Deploy

`optimizer_runs` is tuned **low** (50): at 200 a bb HonkVerifier is 24,644 B
runtime — **over the EIP-170 limit** (24,576 B) and undeployable; at 50 each is
~23,78x B (under). Correctness is unchanged (`forge test` stays green). Both
verifiers and the Registry fit EIP-170; only the `Deploy` *script* (which embeds
both verifiers' creation code) is large, and a script is run, never deployed.

`script/Deploy.s.sol` deploys both verifiers (forge auto-deploys + links each
one's transcript library) and the `Registry` pinned to both:

```sh
# local EVM
anvil &
forge script script/Deploy.s.sol:Deploy --rpc-url http://127.0.0.1:8545 \
  --sender 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266 --unlocked --broadcast \
  --use "$(command -v solc)"

# a testnet: --rpc-url $SEPOLIA_RPC --private-key $KEY --broadcast
```

A `forge script … :Deploy` simulation (no `--broadcast`, no node) deploys + links
in-EVM as a self-contained check.
