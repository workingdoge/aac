# registry — 4/REG, the root registry (Solidity)

The deployable surface that **consumes** the AAC proofs. 4/REG holds books, not
funds: its state is commitments, its update rule is proof, and **its refusals
are the entire trust model**. This is where the Noir/UltraHonk world meets a
chain.

- `src/Registry.sol` — the 4/REG contract. `update(namehash, proof, publicInputs)`
  discharges the TRANSITION/1 verifier contract (3/PROOF §5): **old-root
  equality** (the concurrency rule — each row is its own sequencer), the **context
  pin**, and the **proof** itself, then atomically advances the roots, chains
  `fact_fold`, and bumps the nonce. Anything it cannot verify, it refuses.
- `src/HonkVerifier.sol` — the UltraHonk verifier, **generated by `bb`**
  (`bb write_solidity_verifier -s ultra_honk -k vk`) for the TRANSITION/1 vk.
  Regenerable; do not hand-edit.
- `test/fixtures/transition.{proof,pub}` — a **real** TRANSITION/1 proof (keccak
  oracle, for EVM) + its 8 public inputs, produced by `bb prove --oracle_hash keccak`.

The pipeline, end to end:

```
circuits/transition (Noir)  →  bb prove --oracle_hash keccak  →  HonkVerifier.sol  →  Registry.update()
```

## Test

```sh
cd registry
forge test --use "$(command -v solc)"        # forge + solc from nixpkgs
```

`test_ValidProofUpdatesRow` verifies the **real** proof on-chain (~3.25M gas) and
advances the row; `test_StaleUpdateReverts`, `test_TamperedProofReverts`, and
`test_ContextMismatchReverts` exercise the refusals — the trust model.

## Regenerate the verifier + fixtures

```sh
cd circuits && nargo compile -p transition && nargo execute -p transition
bb prove -s ultra_honk -b target/transition.json -w target/transition.gz \
   -o /tmp/r --oracle_hash keccak --write_vk
bb write_solidity_verifier -s ultra_honk -k /tmp/r/vk -o ../registry/src/HonkVerifier.sol
cp /tmp/r/proof ../registry/test/fixtures/transition.proof
cp /tmp/r/public_inputs ../registry/test/fixtures/transition.pub
```

## Deploy

`optimizer_runs` is tuned **low** (50): at 200 the bb HonkVerifier is 24,644 B
runtime — **over the EIP-170 limit** (24,576 B) and undeployable; at 50 it is
23,782 B (794 B under). Correctness is unchanged (`forge test` stays green).

`script/Deploy.s.sol` deploys the verifier (forge auto-deploys + links its
`ZKTranscriptLib`) and the `Registry` pinned to it:

```sh
# local EVM
anvil &
forge script script/Deploy.s.sol:Deploy --rpc-url http://127.0.0.1:8545 \
  --sender 0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266 --unlocked --broadcast \
  --use "$(command -v solc)"

# a testnet: --rpc-url $SEPOLIA_RPC --private-key $KEY --broadcast
```

Verified deploying to live anvil under EIP-170 enforcement (ONCHAIN EXECUTION
SUCCESSFUL). A `forge script … :Deploy` simulation (no `--broadcast`, no node)
deploys + links in-EVM as a self-contained check.
